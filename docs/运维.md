# InkWeaver 开发与运维

本文覆盖本地基础设施、生产拓扑、数据库迁移、健康检查和仍可执行的排障步骤。完整发布顺序、低内存约束、验收和回滚见 [部署与发布](./部署与发布.md)；FRP 见 [内网穿透与 Embedding 服务](./内网穿透与Embedding服务.md)。运行 Docker、连接服务器、部署、迁移或修改远端系统前，必须取得当前任务授权并确认目标环境。

## 1. 环境文件与秘密

环境文件不纳入 Git：

- 根 `.env`：本地 Docker Compose。
- `apps/server/.env`：本地 NestJS 与 TypeORM CLI。
- 根 `.env.prod`：生产 Compose 与 server 容器。
- `deploy/INSTANCE.local.md`：真实域名、IP 与 SSH 私钥路径；从 `deploy/INSTANCE.local.example` 复制。

不要在文档、提交、终端回显或任务报告中暴露真实密码、Token、私钥、SMTP 凭据或完整环境文件。

### 变量分组

| 分组 | 变量 |
|------|------|
| PostgreSQL | `DATABASE_URL`，或 `DB_HOST`、`DB_PORT`、`DB_USERNAME`、`DB_PASSWORD`、`DB_DATABASE` |
| 本地 Compose | `POSTGRES_PASSWORD`；必须与 server 使用的 `DB_PASSWORD` 对应 |
| Redis | `REDIS_URL`，或 `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD` |
| 认证 | `JWT_SECRET`、`JWT_EXPIRES_IN`（access 默认 `1h`；refresh 固定约 30d） |
| AI / RAG | `AI_CHAT_BASE_URL`、`AI_CHAT_API_KEY`、`AI_CHAT_MODEL`；`AI_EMBED_BASE_URL`、`AI_EMBED_TOKEN`、`AI_EMBED_TIMEOUT_MS` |
| 应用 | `PORT`、`NODE_ENV`、`APP_PUBLIC_URL`、`CORS_ORIGIN`、`TYPEORM_ENABLED` |
| 邮件 | `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASS`、`SMTP_FROM` |
| Web/H5 构建 | `VITE_APP_PUBLIC_URL`、`VITE_API_BASE_URL`、`VITE_SYNC_SOCKET_URL` |
| 生产存储 | `UPLOADS_HOST_PATH`、`MINIO_ROOT_USER`、`MINIO_ROOT_PASSWORD`、`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`、`MINIO_USE_SSL` |

具体默认值与解析逻辑以 `apps/server/src/config/`、客户端 `config/env.ts` 和两个 Compose 文件为准。

## 2. 本地开发

```bash
pnpm install
# 准备根 .env 与 apps/server/.env
docker compose up -d
pnpm dev:server
pnpm dev:web
```

| 服务 | 默认入口 |
|------|----------|
| Server | `http://localhost:3000` |
| H5 | `http://localhost:3001` |
| Admin | `http://localhost:3002` |
| Web | `http://localhost:3003` |
| Mailhog | `http://localhost:8025` |
| PostgreSQL | `127.0.0.1:5432` |
| Redis | `127.0.0.1:6379` |

本地 [docker-compose.yml](../docker-compose.yml) 只启动 PostgreSQL（`pgvector/pgvector:pg16`）、Redis 和 Mailhog；应用进程由 pnpm 命令启动。

## 3. 生产拓扑

[docker-compose.prod.yml](../docker-compose.prod.yml) 运行 PostgreSQL、Redis、MinIO 和 Nest server。Web 静态资源由 Nginx 提供，并将 `/api`、`/sync`、`/socket.io`、`/uploads` 与健康检查转发到后端。

```text
Browser → Nginx ─┬─ Web dist
                 ├─ Nest :3000 ─┬─ PostgreSQL
                 │              ├─ Redis / BullMQ
                 │              ├─ MinIO（新上传，内网）
                 │              └─ uploads volume（历史文件）
                 └─ MinIO console / S3 管理子域
```

配置了 `MINIO_ENDPOINT` 时，新上传（文档图片、头像）写入 MinIO bucket（默认 `inkweaver`），对外 URL 仍为 `/uploads/...`；Nest 的 `/uploads` 中间件优先读本地 volume，未命中再回源 MinIO。未配置 MinIO 时行为与本地开发一致（只写磁盘）。

生产 Compose 已向 server 注入 `MINIO_ENDPOINT=http://minio:9000` 与凭证（同 `MINIO_ROOT_*`）。`UPLOADS_HOST_PATH` 与 MinIO 数据卷仍须分离，不可挂到同一路径。

相关变量：`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`、`MINIO_USE_SSL`。

### AI / RAG（第一期）

- PostgreSQL 镜像为 `pgvector/pgvector:pg16`；迁移会 `CREATE EXTENSION vector` 并创建 `document_chunks`。
- 生成模型：`AI_CHAT_*`（OpenAI 兼容，如 DeepSeek / 通义）。
- 嵌入：本机 `services/embed-service`（bge-small-zh-v1.5），Nest 通过 `AI_EMBED_BASE_URL` 调用；生产使用 FRP TCP 映射并配置独立的 `AI_EMBED_TOKEN`。本机服务见 [services/embed-service/README.md](../services/embed-service/README.md)，完整隧道见 [内网穿透与 Embedding 服务](./内网穿透与Embedding服务.md)。
- Web 入口：`/ai` 笔记问答页。

首次启用向量检索、修复 embedding 后，或需要重建全部派生索引时，在新版 Server
容器内执行幂等回填命令：

```bash
docker exec inkweaver-server node dist/scripts/backfill-document-index.js
```

该命令只处理未删除文档，并通过固定 BullMQ `jobId` 去重；执行完成后仍需确认
`document_chunks` 已生成、失败队列为空，再验证带登录 Token 的 AI 问答和混合搜索。

## 4. 部署资产

| 路径 | 用途 |
|------|------|
| `deploy/scripts/ecs-init.sh` | ECS 初始化、Docker、swap、防火墙和目录 |
| `deploy/scripts/provision-inkweaver-cn.sh` | 当前完整单机 provision 入口 |
| `deploy/scripts/bootstrap-on-server.sh` | 较早的同类 bootstrap；使用前与 provision 脚本比较，避免重复执行 |
| `deploy/scripts/deploy-backend.sh` | 构建并启动生产 Compose，随后检查 `/readyz` |
| `deploy/scripts/build-web-local.sh` | 在开发机生成 Web dist |
| `deploy/scripts/deploy-web.sh` | 通过 tar/scp/ssh 校验、切换、验收 Web，失败自动回滚 |
| `deploy/scripts/setup-nginx-ssl.sh` | 安装 Nginx 配置并申请证书 |
| `deploy/scripts/backup.sh` | PostgreSQL 与 uploads 业务数据备份 |
| `deploy/nginx/` | 单域及 MinIO 子域配置模板 |

完整部署步骤和常见故障见 [部署与发布](./部署与发布.md)。资源充足的服务器可使用标准 Compose 入口：

```bash
docker compose -p repo -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

低内存服务器（当前 ECS 约 1.6GB）不要直接构建 Web 或执行 Server 的
`build --no-cache`：

- Web 在开发机 Git Bash 使用 `build-web-local.sh` 后再执行 `deploy-web.sh`；脚本不依赖 rsync，成功后不保留历史 Web 发布目录。
- Server 应在开发机或 CI 构建 `linux/amd64` 镜像，传到 ECS 后用
  `up -d --no-build --force-recreate server` 替换容器，并保留旧镜像用于回滚。
- 仅当依赖、Dockerfile 和运行时文件均未变化时，紧急热修复才可在本机执行
  `pnpm --filter @inkweaver/server build`，将完整 `apps/server/dist` 覆盖到旧镜像的
  `/app/dist` 形成新镜像。替换前必须验证关键构建产物，不能直接修改运行中容器。

生产机发生 SSH 与 HTTP 同时无响应时应立即停止构建，通过云控制台恢复实例；
恢复后先确认 Shadowsocks、FRPS、PostgreSQL、Redis、MinIO 和 Server 全部正常，
再继续部署。

发布临时回滚与业务数据备份必须分开：Web/Nest 回滚点可在验收成功后清理，
`/opt/inkweaver/backups` 中的 PostgreSQL/uploads 备份不得随镜像或静态目录清理。

## 5. 数据库迁移

| 环境 | 命令或行为 |
|------|------------|
| 本地 CLI | `pnpm --filter @inkweaver/server migration:run` |
| 回滚最近一次 | `pnpm --filter @inkweaver/server migration:revert` |
| 生产容器 | `apps/server/docker-entrypoint.sh` 启动前执行编译后的迁移脚本 |

生产可用 `SKIP_MIGRATIONS=true` 跳过自动迁移，但只能在确认数据库版本兼容时使用。迁移定义位于 `apps/server/src/migrations/`，数据源配置位于 `apps/server/src/data-source.ts`。常用 SQL、全文检索和 pgvector 参考见 [PostgreSQL 数据库操作语句](./PostgreSQL数据库操作语句.md)。

## 6. 健康检查与验收

```bash
curl http://localhost:3000/healthz
curl http://localhost:3000/readyz
```

- `/healthz`：Nest 进程可响应。
- `/readyz`：Redis 必须为 `up`，PostgreSQL 为 `up` 或按配置显示 `skipped`。

代码交付按变更范围运行根 `package.json` 中的 typecheck、lint 与目标 build。生产验收还应覆盖登录、文档编辑与重新加载、同步、搜索/分享、邮件队列和静态资源访问；不得用历史“已完成”状态代替当前验证。

## 7. 常见故障

### `/readyz` 返回 503

检查 server 日志、数据库和 Redis 状态，并确认本地/生产环境中的密码与主机名一致：

```bash
docker compose ps
docker compose -f docker-compose.prod.yml logs server --tail=100
```

### WebSocket 连接到前端端口并超时

Web/H5 的 Vite 或 Nginx 必须同时代理 `/sync` 和 Socket.IO 引擎路径 `/socket.io`。客户端完成 REST 拉取后不应因实时连接失败而长期阻塞页面。

### 生产页面白屏，模块 MIME 为 `text/html`

通常是 Nginx 无权读取 Web dist，或静态资源错误回退到 `index.html`。优先使用 `deploy-web.sh`；手工修复时保证目录可遍历、文件可读，并让 `/assets/` 缺失资源直接返回 404。

### BullMQ 启动时无法注入 `ModuleRef`

pnpm 严格隔离下可能安装出不同物理路径的 `@nestjs/core`。检查 `apps/server` 与 `@nestjs/bullmq` 是否解析到同一实例；依赖只保留在 `apps/server`，不要通过全局安装或随意 hoist 掩盖问题。

### Certbot 报子域 `NXDOMAIN`

先确认申请证书的每个域名都已有指向目标服务器的 DNS 记录。未配置 MinIO 子域时只申请主域，DNS 生效后再扩展证书。

### SSH 密钥用途混淆

代码托管平台密钥不等于云服务器登录密钥。使用 `deploy/INSTANCE.local.md` 记录本机私钥路径，但不得提交该文件或把私钥内容写入文档。

### frpc 进程存在但 embedding 请求超时

ECS 或 frps 重启后，旧 frpc 控制连接可能仍显示存活，但工作连接池已经失效。
按 [内网穿透与 Embedding 服务](./内网穿透与Embedding服务.md) 从本机 8090、控制端口
7000、ECS 18090、Docker bridge 到 `/api/ai/ping` 逐层检查；必要时重启本机 frpc，
不能只依据进程存在或 TCP `Established` 判断隧道健康。
